# v2.1 描画の軽量化

2026-09-18。比較元は `2010fee`（3D FLIGHT v2）。ゲーム本体 `src/core.js` はバイト単位で同一。

## 変更

- 画面外の形状を描画対象から除外。大きな米や長い菌糸の先端が画面内にあれば残る保守的な判定。
- 小さく見える胞子・細い菌糸・遠い米だけ細分数を減らす。静的形状は切替に余裕を持たせる。
- 輪を28本の個別線分から共通メッシュ1個へ。半径と太さを別計算し、衝撃波などの時間変化を維持。
- 動的配列とGPUバッファの容量を再利用。静的な可視形状の並びが変わらなければ再転送しない。
- 発光のぼかしを低解像度へ移動。重みを維持し、全画面合成のテクスチャ参照を6回から2回へ。
- 自動画質は初期ON。処理が重い時に3D画面の解像度を段階調整し、改善しなければ元に戻して調整を控える。HUDは鮮明なまま。
- 操縦、敵AI、当たり判定、発射間隔、移動速度、演出時間、通常描画の間隔は変更なし。

## 同じ条件での計数

3海域 × 6つのXYZ視点 × 縦横2画面 × 3画質 × 通常／上限負荷 = **216条件**。標準画質の各構成は36条件。

| 指標 | 旧版 | 軽量化版 | 変化 |
| --- | ---: | ---: | ---: |
| 標準・通常構成の平均送出三角形 | 204,612 | 27,287 | -86.7% |
| 標準・上限構成の平均送出三角形 | 245,388 | 32,309 | -86.8% |
| 通常構成、同じ視点の次フレームの転送量平均 | 25,820 B | 4,490 B | -82.6% |
| 通常構成の動的形状生成時間・ケース中央値の中央値 | 0.408 ms | 0.147 ms | Node CPUのみ |
| 上限構成の動的形状生成時間・ケース中央値の中央値 | 1.238 ms | 0.338 ms | Node CPUのみ |

標準の開始時構成、1440×900のAPI契約テストでは **189,156 → 75,176三角形（60.3%減）**。上の216条件平均とは別の指標。

## 数値の意味と限界

- CPUで生成・選別した形状と、WebGL APIの代替実装へ渡した呼出しを計数した。実際のGPU・画面・FPSは未測定。
- 視点を均等に混ぜた合成条件。普段のプレイ時間の配分ではないため、実プレイの削減率を保証しない。
- 転送量は同一視点の2フレーム目。旋回して可視範囲や詳細が変わると、静的形状の追加転送が発生する。
- 時間はApple M4 / Node v26.7.0での形状生成のみ。カリング、GPU、描画全体、スマホを含まない。JIT・GC・ホスト負荷に影響される。
- 詳細別にまとめて描くため、開始時の形状の描画呼出しは6→13へ増える。頂点数と転送量を減らす設計で、GPU時間の改善は実測で確かめる必要がある。
- 発光用に小さな作業テクスチャを1枚追加。常駐メモリが全項目で減ったという意味ではない。低画質では発光用の作業領域を作らない。
- 自動画質はフレーム到着間隔を手掛かりにする。OSのフレーム制限とGPU負荷を直接識別できないため、改善しない試行は戻す。

## 維持を確認した内容

- core全体が比較元と同一。
- 米・酵母・胞子の静的変換、機体・敵・弾・酵母の動的変換、敵の鞭毛の時間変化が比較元と一致。
- 輪の太さは半径に依存しない。半径0を除外。
- 大きな形状やカメラ後方に中心がある形状でも、画面内の部分を誤って消さない。
- 保存・開始・停止・勝敗・再挑戦を維持。通常難易度3seedで全救出・ボス撃破・帰還。

## 再現

Git履歴の `2010fee` とNodeが必要。ブラウザは使用しない。

```sh
node tests/render-benchmark.cjs --baseline --out /tmp/shubo-before.json
node tests/render-benchmark.cjs --out /tmp/shubo-after.json
node tests/render-compare.cjs /tmp/shubo-before.json /tmp/shubo-after.json
node tests/render-optimization.cjs
```

証跡：`render-performance.json`（集計・216条件の対応比較・ソースハッシュ）、`render-optimization-verification.json`、`render-contract-verification.json`。
